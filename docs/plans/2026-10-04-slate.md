# The Slate Over the Game Actors: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `Slate` module publishes the slate and its watchability. It joins each league's last good listing with
each game's actor, and it publishes whenever either changes: a burst within 250 ms becomes one publication. Ingest
only polls, and `Watch` is deleted.

**Architecture:** Ingest replaces `slate` and `changes` with `listed`, published on every poll. Cadence reads
`gameActors.liveGames`. `Slate.ts`, at the Hub's top level, combines `ingest.listed` with `gameActors.changes` using
`Stream.zipLatest`, debounces by 250 ms, and folds `Watchability.fold` into a `SubscriptionRef`. HubServer,
StageSessions, and HubMode read from Slate.

**Tech Stack:** Effect 4 (`Context.Service`, `Layer`, `Stream.zipLatest`, `Stream.debounce`, `SubscriptionRef`),
`effect/cluster` through `Cluster.inMemory`, `@effect/vitest` with `TestClock`.

## Facts settled while planning

- `SubscriptionRef.set` publishes on every call, even with an equal value: `setUnsafe` calls `PubSub.publishUnsafe`
  unconditionally (`effect/src/SubscriptionRef.ts:296`). So Ingest keeps a `SubscriptionRef` for `listed`, and
  `changes` emits once per poll. No `PubSub` is needed.
- `Stream.zipLatest(left, right)` emits once both sides have emitted, then on each new value from either side.
  `SubscriptionRef.changes` emits the current value first, so both inputs start straight away.
- `Stream.debounce(duration)` emits the latest value after a quiet pause, on the layer's clock. If inputs keep
  arriving more often than every 250 ms, it never emits. Polls are 10 s apart and FastCast sent 2,195 messages over a
  whole game day, so this does not happen. Note it in Slate's doc comment.
