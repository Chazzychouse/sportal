# Corpus — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carry out `docs/specs/2026-10-07-corpus-design.md`. The fold becomes the **slate**, with stamped game
events and telemetry-only observations. The poll falls back to the push through a held snapshot instead of the tie
rule, and each event kind has one origin. A **corpus** of typed days is built from the feed log or synthesized from
ESPN's archive, and `corpus run` plays days through the slate on virtual time, in parallel.

**Architecture:** One branch, `corpus`, in the worktree `../sportal-corpus`, where the spec is committed. Tasks 1–3
are `refactor:` (renames and reshaping, behaviour unchanged). Tasks 4 and 5 are the `feat:` behaviour changes the spec
lists. Tasks 6–9 add the corpus. Tasks 10–12 add backfill. Task 13 is documentation. Each task is one commit (Task 5
is two), and every commit passes `pnpm check`.

**Tech Stack:** Effect 4 (`effect`, `effect/cli`, `effect/http`, `effect/workers`, `@effect/platform-node`'s
`NodeWorker` and `NodeWorkerRunner`, `@effect/sql-sqlite-node`), Vitest with `@effect/vitest`, Biome,
dependency-cruiser, knip, pnpm workspaces.

**Interfaces:**
- Produces:
  ```ts
  // LiveGame.ts
  export type LiveGameState = Data.TaggedEnum<{
    Upcoming: {}
    Live: { readonly updatedAt: DateTime.Utc }
    /** Live, followed by the push, with a poll snapshot ahead of it held until `until`. */
    Holding: { readonly updatedAt: DateTime.Utc; readonly held: GameSnapshot; readonly until: DateTime.Utc }
    Stale: { readonly updatedAt: DateTime.Utc }
    Over: {}
  }>
  class LiveGame {
    /** How long a covered game holds a poll snapshot ahead of it before the poll's applies. */
    static readonly fallbackAfter: Duration   // 15 s
    /** Live or holding, its snapshot from the push. */
    isCovered(): boolean
    take(delivery, now): { liveGame: Option<LiveGame>; events: ReadonlyArray<GameEventKind>; outcome: TookOutcome }
    tick(now): { liveGame: Option<LiveGame>; events: ReadonlyArray<GameEventKind>; fellBack: boolean }
  }
  // Game.ts
  /** Later in game time, or at the same game time with a different score or status. */
  isAheadOf(that: GameSnapshot): boolean
  // Slate.ts
  SlateObservation.Took.outcome: "taken" | "behind" | "held" | "fellBack"   // "kept" goes
  ```
  `take` and `tick` returning `outcome` / `fellBack` lets `Slate` report `Took` without re-deriving what happened. If
  a cleaner shape shows itself in the code (for example `tick` returning a `Took` observation itself), use it and
  note it in the commit. The rule is that `Slate` must not repeat `LiveGame`'s decisions.

  The tables are the spec's "Merge rules", unchanged. The state diagram:

  ```
  Live ──poll ahead, covered──► Holding ──push not behind held──► Live (from push)
  Holding ──poll ahead of held──► Holding (held replaced, until kept)
  Holding ──tick at until──► Live (from poll, held applied, its state events said)
  ```
