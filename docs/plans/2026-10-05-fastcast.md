## Rules for every task

- State is a tagged union with transitions, never booleans and flags. Payloads become domain values through
  `Schema` transformations, not hand-written `x === undefined ? {} : {…}` spreads.
- Effect's own abstractions, never Node's or raw callbacks: `Socket` (`effect/socket`) over
  `NodeSocket.layerWebSocketConstructorWS` (it uses `ws`, already installed through `@effect/platform-node`; Node's
  built-in `WebSocket` fails ESPN's handshake), `HttpClient`, `Stream.mapAccumEffect` for the document's state,
  `Schedule` for retry. No `node:fs`, `node:zlib`, mutable classes with `Map`s, `for` loops, or `throw` + `Effect.try`.
- Main export first; helpers below as hoisted functions; no option-bag type aliases; no `any`, casts outside
  decoding, non-null assertions, enums, default exports.
- Every exported type name is a `CONTEXT.md` term, added in the same commit.
- Doc comment on each major export; inline comments only where the why is unclear.
- `pnpm check` passes before every commit. Commits are conventional and end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## One deviation from the spec, to approve here

The spec names a `LiveFeed.delivery` span carrying `op` and `mid`, as the parent of the `GameActors.receive` spans.
The adapter knows `op` and `mid`, but the receives happen in Ingest after the stream emits, so no single span can carry
both. This plan makes **`Ingest.push`** the parent span (`sportal.leagues`, `sportal.games`, `sportal.unlisted`), and
puts `op` and `mid` on the adapter's Debug log line and the `sportal_live_feed_messages` counter.

### Task 4: FastCast's document, as snapshot batches

**Files:** create `FastCastPayload.ts`, `FastCastDocument.ts`, `FastCastDocument.test.ts`; check out the three fixtures
from `live-feed-design`.

**Wire shapes (`FastCastPayload.ts`).** `Message`, a `Schema.Union` of tagged structs keyed by `op`:

| `op` | Struct | Carries |
| --- | --- | --- |
| `C` | `Connected` | `sid` |
| `S` | `Subscribed` | `tc` |
| `H` | `Checkpoint` | `tc`, `mid`, `pl`: the checkpoint's URL |
| `R`, `P` | `Patched` | `tc`, `mid`, `pl` decoded **by a schema transformation** to `ReadonlyArray<Patch>`: `pl` is base64 zlib, JSON text, or an array. Inflate with the web `DecompressionStream("deflate")` inside an effectful `SchemaGetter` (see `ai-docs` on transformations); no `node:zlib` |
| `I` | `Idle` | `tc`, `mid` |
| `B` | `Heartbeat` | — |

`Patch` (`add`, `replace`, `remove`, `copy`; `path`, `from`, `value`), `Host` (`ip`, `securePort`, `token`),
`CheckpointDocument` (`sports[].leagues[].events[]`), and `Event`, the one game, which decodes **straight to a
`GameSnapshot`** through a transformation using `EspnSnapshot` from Task 2. FastCast's competitor is the team itself
(no `team` wrapper) and has no `shortDisplayName`; use `displayName` for the short name, since Ingest replaces the
names with the poll's (Task 7).

**State (`FastCastDocument.ts`).** Per topic, a `Data.TaggedEnum`:

```ts
type Topic = Data.TaggedEnum<{
  AwaitingCheckpoint: {}
  Synced: { readonly mid: number; readonly games: ReadonlyMap<EventUid, Schema.Json> }
}>
```

| From | Message | To | Emits |
| --- | --- | --- | --- |
| any | `H` (checkpoint fetched over `HttpClient`) | `Synced { mid, games }` | every game |
| `Synced { mid: n }` | `R`/`P` with `mid` n+1 | `Synced { mid: n+1, games patched }` | the games touched |
| `Synced { mid: n }` | `I` with `mid` n+1 | `Synced { mid: n+1 }` | nothing |
| `Synced { mid: n }` | `R`/`P`/`I` with another `mid` | — | fails, `Gap` |
| `AwaitingCheckpoint` | `R`/`P`/`I` | — | fails, `Gap` |
| any | a patch `JsonPatch.apply` rejects | — | fails, `Unapplicable` |
| any | `C`, `S`, `B`, another league's topic | unchanged | nothing |

```ts
/** The games of each league's scoreboard topic, one batch per message that changes any. */
export function batches(
  leagues: ReadonlyArray<LeagueId>,
  messages: Stream.Stream<typeof FastCastPayload.Message.Type, LiveFeedError>
): Stream.Stream<ReadonlyArray<GameSnapshot>, LiveFeedError, HttpClient.HttpClient>

/** The scoreboard topic carrying `league`'s games. */
export function topic(league: LeagueId): string
```

Fold with `Stream.mapAccumEffect` over a `ReadonlyMap<LeagueId, Topic>`. A patch's path starts with the event uid
(`s:20~l:28~e:<id>~c:<id>`), then a JSON Pointer into that event; apply with `JsonPatch.apply` to that event's JSON.
`JsonPatch` has no `copy`: a `copy` becomes an `add` of the value read at `from` (`JsonPointer` for the tokens). An
event that fails to decode is skipped with a Warning (`league`, uid) and counted.

**Telemetry it owns:** `sportal_live_feed_messages` {`league`, `op`}, `sportal_live_feed_games` {`league`},
`sportal_live_feed_undecoded` {`league`}; one Debug log per message with `league`, `op`, `mid`, games touched.

### Task 5: The socket

**Files:** create `apps/hub/src/provider/espn/FastCast.ts`.

```ts
/** ESPN FastCast as the live feed: one socket subscribed to each league's scoreboard topic. */
export const layer: Layer.Layer<LiveFeed, never, HttpClient.HttpClient | Socket.WebSocketConstructor>
```

- Host: `GET https://fastcast.semfs.engsvc.go.com/public/websockethost`, decoded as `Host`; a failure is `Refused`.
- Socket: `Socket.makeWebSocket("wss://<ip>:<securePort>/FastcastService/pubsub/profiles/12000?TrafficManager-Token=<token>")`.
  Read with `Socket.toChannelString` into a `Stream`, decoding each text as `FastCastPayload.Message`. Write
  `{"op":"C"}` on open and `{"op":"S","sid":…,"tc":topic(league)}` per league on `Connected`, through the socket's
  `writer`. A close or socket error is `Closed`.
- Silence: `Stream.timeoutOrElse` at 45 s fails with `Silent`. `B` heartbeats arrive about every 10 s, so a healthy
  quiet connection never trips it.
- Span `FastCast.connect` (`sportal.topics`) around the host request and the subscription.
- `sportal_live_feed_connected` gauge: 1 once subscribed, 0 when the stream's scope closes (a finalizer).
  `sportal_live_feed_connects` counter: +1 per subscription. Info log on each connect.

No unit test: the protocol is Task 4's. Verified against ESPN in Task 9.

- [ ] Implement, `pnpm check` (commit with Task 8 if knip reports `layer` unused), commit

### Task 7: Ingest runs the live feed

**Files:** `apps/hub/src/ingest/Ingest.ts`, `Ingest.test.ts`; add `LiveFeed.none` where `Ingest.layer` is built in
`Slate.test.ts`, `http/HubServer.test.ts`, `scenario/ScenarioProvider.test.ts`.

`Ingest.layer` now also requires `LiveFeed`. In its scope it forks:

```
liveFeed.games(leagues)
  → each batch: push(batch)          (span Ingest.push)
  → on error: Warning log with reason, sportal_live_feed_errors {reason} +1
  → Stream.retry(Schedule.exponential("1 second") jittered, each delay capped at 1 minute)
```

`push(batch)`: for each pushed game, find its game in the per-league listing Ingest already keeps (`byLeague`).
Listed: `receive(listed.advancedTo(pushed), "push")`, all concurrently, each awaited, as the poll does. Not listed:
skip and count `sportal_live_feed_unlisted` {`league`}. The poll loop and `Cadence` do not change.

The listing map becomes shared between the poll fiber and the push fiber: hold it in a `Ref` (or the existing
`SubscriptionRef`'s companion), not a mutable `Map`.

- [ ] **Tests first** (test clock, `TestCluster.gameActors`, a test `LiveFeed` whose stream reads a `Queue` the test
  offers to):
  - a pushed game reaches its actor between polls, with the poll's team names and the push's clock
  - a pushed game not on any listing is not sent, and `sportal_live_feed_unlisted` counts it
  - a feed that fails with `Closed` is subscribed again after 1 s of test time, then after about 2 s; the poll keeps

  - `Ingest.push` is the parent of the `GameActors.receive` spans it causes (`recordingSpans`)
