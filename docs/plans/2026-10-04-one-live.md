# One "Live" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every part of Sportal gives the same answer to "is this game live?". A game delayed mid-game is live everywhere: on its tile, the strip, the Remote, and in Watchability.

**Architecture:** `GameSnapshot.progress()` is the only answer, and `GameSnapshot.isLive()` is deleted. Today they disagree only for `delayed` with `period >= 1`: `progress()` says live, `isLive()` says not. Fix `2c986cc` moved Cadence, `Guide.airs` and the top bar's count to `progress()`. This plan moves the remaining 11 callers.

**Behaviour change, approved 2026-10-04:** Watchability scores a game delayed mid-game for closeness, situation and stakes, as it does any live game, and still counts it as a lull. Today such a game scores 0 with no reasons. The lull is what keeps the Director from choosing it; the score says how good the game will be when it resumes.

**Tech Stack:** Effect 4 domain classes, React 19, `@effect/vitest`.

**Source:** architecture review of 2026-10-04, candidate 2. No spec: this is a deletion plus one approved behaviour change. Work only in the worktree `/home/chazzy/development/projects/sportal/.worktrees/one-live` (branch `one-live`). Never edit files or switch branches in the main checkout.

## Global Constraints

- `delayed` with `period 0` stays upcoming, as `progress()` already says.
- "Scores mean something" stays `live or final`. It does not become `progress() !== "upcoming"`, because postponed and canceled games are over but have no meaningful score.
