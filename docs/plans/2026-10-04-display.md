# The Display Module: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One pure, immutable `Display` owns a Display's local state: the selected tile, the interacting tile, the
pick, the slate drawer, and the one open overlay. It answers each input with `{ display, commands }`. App, TopBar,
and the Remote use it instead of their own copies of its rules.

**Architecture:** `apps/web/src/Display.ts` is a `Data.Class` with methods, plus a private `Data.taggedEnum` for the
overlay. `StripCards.drop` folds into `Display.drop`. App keeps one `useState(Display.initial)` and a local `apply`
that sets the display and dispatches the commands. The Remote does the same with `select` and `drop` only.

**Tech Stack:** Effect 4 `Data.Class` and `Data.taggedEnum`, React 19, `@effect/vitest`.

**Spec:** `docs/specs/2026-10-04-display-design.md`. Its transition table is the requirement. Work only in the
worktree `/home/chazzy/development/projects/sportal/.worktrees/display` (branch `display`). Never edit files or switch
branches in the main checkout.

### Task 1: Display and its transitions

**Interfaces:** the `Display` class as in the spec's "`apps/web/src/Display.ts`" section: the fields, `initial`,
`selectedOn`, `interactingOn`, `press`, `select`, `drop`, `toggleSlate`, `open`, `close`. `cards` is
`ReturnType<typeof stripCards>`, and `nextPick` stays in `StripCards.ts` and is called from `press(StepPick)`.

- [ ] **Step 1: Failing tests** in `apps/web/src/Display.test.ts`. Build stages the way `StripCards.test.ts` does,
  with its `withTiles` helper shape and test games from `@sportal/domain/TestGame`. There must be one test per row of
  the spec's transition table, plus the eight named cases in the spec's Testing section. The ones most likely to be
  missed:
  - Esc with the key help open while soloed closes the help and returns no commands.
  - After a swap moves another game into the selected slot, `interactingOn` is `undefined`.
  - `selectedOn` is 0 after the layout shrinks to Single from a Quad with slot 3 selected, and `drop` then assigns
    into slot 0.
  - `open("Palette")` with Keys open leaves only Palette open.
  - `press(FullScreen)` returns the same display and no commands.
  - Copy `StripCards.test.ts`'s two `drop` tests here, reworded against `Display.drop`. They are deleted from there
    in Task 2.
- [ ] **Step 2:** Run `pnpm vitest run apps/web/src/Display.test.ts` and confirm it fails (the module is missing).
- [ ] **Step 3: Implement** `Display.ts`. The order is the class, then private helpers below it, in the order they are
  first used. `drop` holds the logic of `StripCards.drop` (free → `Assign`, bench → `Swap`, on stage → nothing; next
  selection `stage.nextEmptySlot(selected) ?? selected`) against `selectedOn(stage)`, and also sets the pick.
  `StripCards.drop` stays until Task 2, so this commit compiles. Note the duplication in the report; Task 2 removes it.
- [ ] **Step 4:** Run `pnpm check`. Commit: `feat(web): Display, a Display's local state and its rules`.

### Task 2: App, TopBar, and the Remote use Display; StripCards.drop is gone

- [ ] **Step 1: App.tsx.**
  - Replace the selected, interacting, pick, slate-open, palette, keys, and join-Remote `useState`s with one
    `useState(Display.initial)` and a local `apply({ display, commands })` that sets it and dispatches each command
    (`dispatch` from `hub/HubClient.ts`).
  - `useHotkeys` handles `FullScreen` with `fullScreen.toggle()` and passes every other hotkey to
    `display.press(hotkey, live.stage, cards)`.
  - Children get `display.selectedOn(live.stage)` and `display.interactingOn(live.stage)`.
  - `StageView.onSelect` calls `display.select`, `SlateView.onDrop` calls `display.drop`, and dialogs'
    `onOpenChange(false)` calls `display.close()`.
  - TopBar's `onKeys` and `onRemote` call `display.open("Keys")` and `display.open("JoinRemote")`, and its slate
    toggle calls `display.toggleSlate()`.
- [ ] **Step 2: TopBar.tsx.** Its solo button no longer builds a command. It calls a new `onToggleSolo` prop, and App
  passes `() => apply(display.press({ _tag: "ToggleSolo" }, live.stage, cards))`. Its `disabled` check reads the
  `selected` it is given, which is now `selectedOn`.
- [ ] **Step 3: RemoteView.tsx.** Replace its `selected` `useState` with `useState(Display.initial)`, and its own
  `apply` that dispatches. Rows call `display.drop`. A row is disabled when `drop` would send no commands
  (`display.drop(card, live.stage).commands.length === 0`); compute that once per row. The stage map gets
  `display.selectedOn(live.stage)`, and its `onSelect` calls `display.select`.
- [ ] **Step 4:** Delete `drop` from `StripCards.ts`, and its `describe("drop")` from `StripCards.test.ts`.
- [ ] **Step 5:** Run `grep -rn "useState" apps/web/src/App.tsx`. Expect no matches for selected, interacting, pick,
  slate, keys, palette, or joinRemote.
- [ ] **Step 6:** Run `pnpm check`. Commit: `refactor(web): App, the top bar, and the Remote take their rules from Display`.
- [ ] **Step 7:** **Hand to the user to run.** Per memory, Electron rendering from an agent shell is unreliable on
  this machine. The user runs `pnpm dev` from this worktree and checks the Task 3 checklist rows.
