> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carry out `docs/specs/2026-10-06-ts7-design.md`. The workspace moves to TypeScript 7.0.2 with
`@effect/tsgo` 0.50.0 patching `tsc`. dependency-cruiser keeps a private TypeScript 6. The Effect diagnostics run
in `pnpm check` and in the editor, and the code they flag is fixed.

**Architecture:** One branch `ts7` in the worktree `../sportal-ts7` (it exists, with the spec committed). Task 1
upgrades the toolchain without the plugin, so it is a pure compiler swap. Task 2 turns the plugin on, measures,
and stops at a gate if the backlog is large. Task 3 fixes what Task 2 found, one commit per package, then commits the plugin. Task 4 updates the docs.

**Tech Stack:** TypeScript 7 (native `tsc`), `@effect/tsgo`, Effect 4, pnpm 12 workspaces, dependency-cruiser 18.5,
knip, Biome, Vitest.

## Global constraints

- Read `AGENTS.md` and `CONTEXT.md` before any task. Their rules apply to every line written here.
- Exact pins: `"typescript": "7.0.2"` and `"@effect/tsgo": "0.50.0"`. No caret. `@effect/language-service` is never
  installed.
- The tsconfig plugin entry is `{ "name": "@effect/language-service" }`. That string is how `@effect/tsgo` finds its
  settings; its schema accepts no other value.

  the conflict. A rule that merely flags a lot of code is fixed, not silenced. No `@effect-diagnostics` line
  suppressions.

  and the example it points to for the API at hand.
- Behaviour is preserved. Existing tests keep their assertions.
- `pnpm check` passes before every commit.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Never edit, install in, or switch branches in the main checkout `../sportal`. The user runs the app from there.

**Interfaces:**

- [ ] **Step 1: Record the dependency-cruiser baseline on TypeScript 6**

Run: `pnpm exec depcruise apps packages 2>&1 | tail -3`
Expected: `✔ no dependency violations found (N modules, M dependencies cruised)`. Write down N and M.

- [ ] **Step 2: Pin the packages and add the prepare script**

In root `package.json`:
- `devDependencies`: `"typescript": "7.0.2"` (replacing `^6.0.3`), add `"@effect/tsgo": "0.50.0"`. Keep the keys
  sorted.
- `scripts`: add `"prepare": "effect-tsgo patch --typescript --no-oxlint"`.

- [ ] **Step 3: Give dependency-cruiser its own TypeScript 6**

Append to `pnpm-workspace.yaml`:

```yaml

    dependencies:
      typescript: ^6
```

- [ ] **Step 4: Install**

Run: `pnpm install`
Expected: the lockfile updates, and the `prepare` output reports the TypeScript integration patched. If pnpm
refuses the new lockfile under its supply-chain policy, stop and report the message. Do not loosen the policy.

- [ ] **Step 5: Verify the patched compiler**

Run: `pnpm exec tsc --version`
Expected: `Version 7.0.2+effect-tsgo.0.50.0` (or equivalent text containing both).

Run: `find -L node_modules/.pnpm -path '*typescript@7.0.2*' -name '*.original' | head`
Expected: one `.original` backup next to the native binary. That shows the patch renamed the store's hard link
aside instead of writing over it.

- [ ] **Step 6: Verify dependency-cruiser sees TypeScript 6**

Run: `node -e "console.log(require(require.resolve('typescript/package.json', {paths: [require('fs').realpathSync('node_modules/dependency-cruiser')]})).version)"`
Expected: `6.x.y`.

Run: `pnpm exec depcruise apps packages 2>&1 | tail -3`
Expected: the same N modules and M dependencies as Step 1, and no violations.

- [ ] **Step 7: Prove a boundary still fails**

### Task 2: Turn on the Effect language service and measure

**Files:**
- Modify: `tsconfig.base.json`

**Interfaces:**
- Consumes: the patched `tsc` from Task 1.
- Produces: a table of Effect diagnostics (rule × package, with counts and severities) handed to Task 3 and shown
  to the user.

- [ ] **Step 1: Add the plugin**

`tsconfig.base.json` becomes:

```jsonc
{
  "$schema": "./node_modules/@effect/tsgo/schema.json",
  "compilerOptions": {
    // …every existing option, unchanged…
    "plugins": [{ "name": "@effect/language-service" }]
  }
}
```

Exit-code options stay at their defaults. No `diagnosticSeverity` yet.

- [ ] **Step 2: Confirm every workspace inherits it**

Run: `for p in packages/domain packages/api apps/hub apps/web apps/desktop; do echo "== $p"; pnpm exec tsc -p $p --showConfig | grep -A3 plugins; done`
Expected: each prints the `@effect/language-service` plugin entry.

- [ ] **Step 3: Measure**

Run, for each of the five workspaces and the root:

```bash
pnpm exec effect-tsgo diagnostics --project "$PWD/<workspace>/tsconfig.json" --format json > "$SCRATCHPAD/diag-<name>.json"
```

(`$SCRATCHPAD` is the session scratchpad directory, never the repo.) Then also run `pnpm typecheck` and confirm the same set of
diagnostics fails it.

Build a table: one row per rule, columns per package, cells are counts, plus the rule's severity. Under it, list
each rule that touches code AGENTS.md allows (React handlers, Electron callbacks, `main.ts`'s process edge,
decoding casts) and name the AGENTS.md line it conflicts with.

- [ ] **Step 4: Gate**

If `pnpm typecheck` passes, commit (Step 5) and skip Task 3.

Otherwise, **stop and report the table to the user**. Do not commit and do not fix anything. The user decides,
from the table, whether Task 3 fixes everything here, or whether this branch lands with
`"ignoreEffectWarningsInTscExitCode": true` and the warnings go to a follow-up.

- [ ] **Step 5: Commit (only if the typecheck passes)**

```bash
git add tsconfig.base.json
git commit -m "build: the Effect language service runs in tsc and the editor

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"
```

### Task 3: Fix what the Effect diagnostics flag

Runs only after the user has seen Task 2's table and chosen to fix it on this branch. The table is the task list.

**Files:**
- Modify: `tsconfig.base.json` (Task 2's uncommitted plugin, plus conflict entries; committed last)
- Modify: the source files the table names

**Interfaces:**
- Consumes: Task 2's table and the user's decision.
- Produces: `pnpm check` passing with the plugin on.

- [ ] **Step 1: Settle the conflicts first**

For each rule the table marks as conflicting with AGENTS.md, add the narrowest entry that removes the conflict,
with a `//` comment naming the AGENTS.md rule. Prefer an `overrides` entry scoped by `include` glob (for example,
`asyncFunction` off for `apps/web/src/**/*.tsx` React handlers, if the table shows that) over a global
`diagnosticSeverity`. Keep the default `floatingEffect: "error"` override for `src/**/*.ts`, since an `overrides`
array replaces the default.

Run: `pnpm typecheck`
Expected: only the non-conflict diagnostics remain.

- [ ] **Step 2: Fix by package, domain first**

Order: `packages/domain`, `packages/api`, `apps/hub`, `apps/desktop`, `apps/web`. For each package:

1. Fix every diagnostic in it. Use what AGENTS.md says to use: time from `Clock`, logic as `Effect` instead of
   `async`, expected failures as tagged errors, decoding through Schema, `Effect.fn` where the rule asks for it.
   Read the rule's page (`https://github.com/Effect-TS/tsgo/blob/main/docs/rules/<kebab-name>.md`) before the
   first fix of each rule, and the matching `effect/ai-docs` example before writing the replacement.
2. Where a diagnostic's quick fix exists, its result is acceptable only if it reads like the surrounding code.
3. Run `pnpm exec tsc -p <package> --noEmit` until clean, then `pnpm vitest run <package>`. Tests must pass with
   unchanged assertions.
4. `pnpm check`, then commit:

```bash
git add <files>
git commit -m "refactor(<package>): what the Effect language service flags

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"
```

Each of these commits holds source fixes only. The plugin and conflict entries in `tsconfig.base.json` stay an
uncommitted change in the worktree for the whole task, so you can see the diagnostics while you work. Before each
commit, run `git stash push tsconfig.base.json && pnpm check && git stash pop`. That checks exactly what is
committed: the fixes preserve behaviour and pass without the plugin.

- [ ] **Step 3: Commit the plugin**

Run: `pnpm check` with `tsconfig.base.json` in place.
Expected: PASS with the plugin on.

```bash
git add tsconfig.base.json
git commit -m "build: the Effect language service runs in tsc and the editor

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"
```

Run: `git diff main --stat -- '*.ts' '*.tsx'`. Every changed source file is accounted for by a row in Task 2's
