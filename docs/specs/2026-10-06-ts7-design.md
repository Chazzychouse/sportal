# TypeScript 7 and the Effect language service — design

Status: approved in brainstorming, 2026-10-06.

The workspace is on TypeScript 6.0.3. TypeScript 7 (7.0.2, released 2026-07-08) is the native Go compiler:
same type checker, several times faster, and the only version the Effect language service now supports.
The old `@effect/language-service` plugin rode on tsserver, which TS 7 no longer ships; its README now says
"If you are using TypeScript 7.0 or newer, use `@effect/tsgo` instead." `docs/technical-spec.md` held the
upgrade back because dependency-cruiser could not run on TS 7. This spec moves the workspace to TS 7,
keeps dependency-cruiser working, and turns on the Effect diagnostics in the editor and in `pnpm check`.

## Scope

- **In:** root `package.json`, `pnpm-workspace.yaml`, `tsconfig.base.json`, the lockfile, AGENTS.md,
  `docs/technical-spec.md`, and whatever source the new Effect diagnostics flag.
- **Behaviour is preserved.** Source changes are diagnostic fixes only, written the house way (Clock,
  `Effect.fn`, tagged errors, Schema decoding).
- **Out:** Oxlint (the repo lints with Biome); editor files in the repo (the Neovim config lives in the
  user's dotfiles and already keys off `node_modules/@effect/tsgo`; no `.vscode/`); project references or
  `tsc -b`; replacing dependency-cruiser.

## Delivery

One branch, `ts7`, in the worktree `../sportal-ts7`. Commits: the toolchain upgrade (`build:`), then the
diagnostic fixes (`refactor:`, split by package when large), then the spec update (`docs:`). Each passes
`pnpm check`. Then `plannotator review` on the branch and one merge to main. Branches open at the time
(`hub-one-path`, `guide-only`, `mlb-postseason`) rebase on whichever lands first; the lockfile and any file
the fixes touch are where they will conflict.

## 1. Packages

| Package | Where | Version | Why |
|---|---|---|---|
| `typescript` | root devDependency | `7.0.2`, exact | `@effect/tsgo` 0.50.0 supports 7.0.2; the patch replaces this exact binary |
| `@effect/tsgo` | root devDependency | `0.50.0`, exact | The Effect language service for TS 7: a patched `tsgo` with Effect diagnostics, quick fixes, refactors |

`@effect/language-service` is not installed.

The root gains a `prepare` script, `effect-tsgo patch --typescript --no-oxlint`, so every `pnpm install`
patches `node_modules/typescript`'s native binary in place. After it, `tsc --version` reports
`7.0.2+effect-tsgo.0.50.0`, `tsc --noEmit` reports Effect diagnostics, and `tsc --lsp --stdio` serves them to
the editor. Upgrading either package later means bumping both together to a pair `@effect/tsgo` lists as
supported.

## 2. dependency-cruiser keeps a private TypeScript 6

dependency-cruiser 18.5 parses TypeScript through the TS JS API, which TS 7.0 does not ship. With TS 7
resolved it cruises zero modules and still exits 0, so `pnpm structure` would pass while checking nothing.
Its author waits for 7.1's public API.

`pnpm-workspace.yaml` gains:

```yaml
# dependency-cruiser parses through the TypeScript JS API, which TS 7.0 does not ship. Drop this once it
# supports TS 7.1.
packageExtensions:
  dependency-cruiser:
    dependencies:
      typescript: ^6
```

dependency-cruiser then resolves its own TS 6 while every workspace and every other tool sees TS 7. Every
rule in `.dependency-cruiser.cjs` keeps working, including `tsPreCompilationDeps` and the type-only
exception in `no-circular`.

**Proof it works**, run once and recorded in the plan, not added to `pnpm check`: `depcruise apps packages`
reports a module count above zero, and a deliberately forbidden import (a web file importing from the Hub)
fails it.

## 3. tsconfig

`tsconfig.base.json` gains:

```jsonc
{
  "$schema": "./node_modules/@effect/tsgo/schema.json",
  "compilerOptions": {
    // …existing options…
    "plugins": [{ "name": "@effect/language-service" }]
  }
}
```

`@effect/language-service` here is the name `@effect/tsgo` reads its settings block by; its schema accepts
no other value. The five workspace tsconfigs and the root `tsconfig.json` extend the base and override only
`lib`, `jsx`, `module`, `moduleResolution`, `types` and `paths`, so they inherit the plugin.

Exit-code options stay at their defaults: Effect errors and warnings fail `tsc`, suggestions do not. The
default `overrides` block (`floatingEffect` is an error under `src/**/*.ts`) stays.

A rule is turned off or downgraded in `diagnosticSeverity` only when it conflicts with a rule in AGENTS.md,
with a `//` comment naming the conflict. A rule that merely flags a lot of code is fixed, not silenced.

No TS 7 compiler-option changes are expected: the base uses none of the options 7 removes (`target: ES5`,
`moduleResolution: node10`/`classic`, `baseUrl`, `downlevelIteration`, `outFile`, and the like). If 7
reports one, it is changed to its 7 equivalent in the toolchain commit.

## 4. Effect diagnostics clean-up

1. With the toolchain in place, run `pnpm typecheck` and tabulate the Effect diagnostics by rule and by
   package.
2. **If the list is modest** (judged at the time, roughly a session's work), fix it all on this branch.
3. **If it is large**, stop and bring the table to the user before fixing anything. Options then include
   landing the toolchain with `ignoreEffectWarningsInTscExitCode: true` and working the warnings down in a
   follow-up.

Fixes follow AGENTS.md: time from `Clock`, logic as `Effect` rather than `async`, expected failures as tagged
errors, decoding through Schema. Framework edges keep `async` where AGENTS.md allows it (React handlers,
Electron callbacks); if a rule such as `asyncFunction` flags those, that is a conflict under §3 and the
rule is scoped off for those files with an `overrides` entry, not suppressed line by line.

## 5. Docs

`docs/technical-spec.md`'s Language row becomes: TypeScript 7 with the Effect language service
(`@effect/tsgo`), `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `erasableSyntaxOnly`;
dependency-cruiser runs on a private TypeScript 6 until it supports 7.1. AGENTS.md's Commands section notes
that `pnpm install` patches `tsc`, so the Effect diagnostics appear in `pnpm check` and the editor.

## Done when

- `pnpm check` passes on the branch.
- `pnpm exec tsc --version` reports `7.0.2+effect-tsgo.0.50.0`.
- The dependency-cruiser proof in §2 holds.
- In the user's Neovim, a `.ts` file in the worktree attaches the `tsc` server (not vtsls) and shows an Effect
  diagnostic on a deliberately floating `Effect.log("x")`. The user checks this; the agent shell cannot.
